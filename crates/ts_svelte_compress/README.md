# Native asset compression

`compress`, `compress_with_limit` and `compress_batch` encode supplied bytes with
pure Rust flate2/miniz_oxide and rust-brotli. There are no C codec dependencies,
filesystem operations, Node execution, clocks or worker threads. The same crate
exports `compress_request_json` through wasm-bindgen on wasm32.

Adapter-node 5.5.4 jobs can deserialize directly into `Job`: copy each required
source from the packaging plan into `Batch.sources`, preserve the source digest
and destination, then call `compress_batch`. Convert each returned `Output` into
the adapter's `CompressionOutput` using `source_sha256` and `bytes`. The codec also
returns the output SHA-256 and fully resolved parameters for artifact identity.
It does not depend on the Kit crate.

The adapter profile selects gzip level 9 with MTIME 0, OS 3, no optional header
fields and Brotli text mode, quality 11, window 22, actual source byte size hint.
Other Brotli parameters retain upstream defaults (automatic block size, normal
window, dictionary and literal context modelling). The installed Node Brotli
header defines default window 22; adapter-node overrides mode, quality and size
hint. Node v24.21.0's embedded `lib/zlib.js` forwards the provided Brotli params
without overriding unspecified values. Tests retain gzip and Brotli reference
vectors generated by that Node version for `hello world\n`.
Output headers are deterministic across native and WASM. Pure Rust encoder
bitstreams are not promised byte-identical to Node's zlib/Brotli implementations;
decoded bytes and selected codec options are the compatibility contract.

Each source is limited to 16 MiB, total source inventory to 64 MiB, repeated job
input to 128 MiB, aggregate output to 96 MiB and jobs/sources to 1,024. Batches run
sequentially and validate every identity/options tuple before starting. Output
writes are bounded during encoding. Codec working memory is additional to input
and output buffers; run WASM compression in a disposable worker. A WASM trap is
terminal for that worker; callers must not treat it as a completed compression.

JSON requests/responses have an additional 16 MiB limit and use numeric byte
arrays. Use the typed API for larger native batches. Requests are:

```json
{"op":"compress","bytes":[104,105],"compression":{"format":"gzip","level":9}}
```

```json
{"op":"compressBatch","batch":{"sources":{},"jobs":[]}}
```

Replies contain `ok` and either `result` or an explicit `error`. Batch result keys
are destination identities. No partial successful batch is returned on failure.
