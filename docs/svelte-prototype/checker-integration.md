# Checker integration notes

Read-only investigation by `/root/projection_investigation`, 2026-10-10.

The first checker adapter will consume one isolated project per process, using
unchanged `ts_goport` interfaces already used by `ts_wasm`: `command_line`,
`TscCompilationHooks`, `new_os_system`, and `new_diagnostic_response`.
Capture auxiliary output with `OsSystem::with_writer`; retain full recursive
`messageChain` and `relatedInformation`. Run on the existing maximum-stack-size
worker model. A panic or nonempty unported report is an incomplete check, never
an empty successful diagnostic list. Disable emit, build, watch and arbitrary
CLI argument forwarding.

Keep complete `.svelte.tsx` or `.svelte.jsx` projections, with typed re-export
bridges in both `.svelte.d.ts` and `.d.svelte.ts`. Preserve exact copied mappings.
Checker diagnostic `pos`/`end` are absolute UTF-16: convert to generated bytes,
map exact spans, then convert to original editor coordinates recursively.
Unmapped and fileless diagnostics remain visible.

Actual declaration inputs, relative to the application's installed packages:

- `svelte-check/dist/src/svelte-shims-v4.d.ts`
- `svelte/svelte-html.d.ts`
- `svelte/elements.d.ts`
- `svelte/types/index.d.ts`

The installed projection shim matches the backend's vendored shim at SHA256
`f2dfa79c9e867a25d3887446b730f8fbdeaa9b74db3eeab196a2d251227a96a5`.
Use the real declarations, including generic component and rune contracts.

Svelte's `declare module '*.svelte'` fallback can hide missing components. For
isolated testing, copy the declaration file and blank only that block, preserving
length and lines. Redirect its exact ambient module names to the copy with
`paths`. Avoid loading the original declarations again through triple-slash type
references: blank generated references in place and use a `typeRoots` forwarding
stub for `svelte`, while including the real copied declarations explicitly. The
stub prevents duplicate declaration loading; it supplies no replacement types.
Do not include `svelte-jsx-v4.d.ts` alongside `svelte-html.d.ts`.

Initial fixtures: valid typed props, wrong prop type, missing required prop,
invalid template member, undefined name, missing component import, and emoji
before an error. This establishes bounded checking and mapping evidence, not
SvelteKit or language-tools parity. Generated ignore regions require separate
validation; do not silently discard their diagnostics.
